# 001 方法：把一个 skill 改造成「协议 + 存储 + 可 pull 的流程」

本篇是 skill-refactor 的判据。分析一个 skill、产出改造方案、检查改造结果，都照这里的条目来；
每条带编号，方案和检查结果里引用编号，读的人能对回来。

这些条目来自一次真实改造（一个验收 skill 从「长手册 + 执行者自己记」改成「命令清单 + 卡片 + 工具算下一步」）里踩过的坑。

## 为什么要改

一个 skill 通常是一份写给 agent 的长手册，加几个脚本。跑久了会出现同一组问题：

- **做到哪了靠执行者记**：会话一断、换一个 agent，就从头猜。
- **人的回答只在聊天里**：执行者照着做了却没记，下一轮又问一遍；或者转述时走了样。
- **规则写在手册里**：执行者照样漏，漏了也没人发现。
- **状态散在多种文件里**：几个脚本各自整文件改写同一个 JSON，互相覆盖。
- **两处各算各的「还剩什么」**：看板说没做完，执行者那边却没有对应的待办。

改造的目标：**做到哪了由工具从记录里算，人和规则的约束由工具执行，执行者只做判断。**

## 一、协议（P）

工具不在任何 agent 框架里面，不能往执行者的工具列表里注册工具。所以照各家通用的工具定义格式，出一本命令清单，执行者照它拼命令行。

- **P1 命令清单就是工具定义。** 每条命令：`name`（字母数字下划线）、`description`（用途、什么时候用、什么时候别用）、
  `input_schema`（JSON Schema，`additionalProperties:false`，字段说明里写规则）、`argv`（命令行模板）、`returns`（`--json` 时返回什么）。
- **P2 清单和参数解析共用一份定义。** 清单外的参数一律拒收：静默忽略会让「更新」变成看不出来的空操作。
- **P3 `--json` 时 stdout 只有一份 JSON。** 返回被改动的那张卡片（最新的完整状态，不是 diff）；
  批量命令一项一个结果，被拒的项带 `refused`；整条命令没执行时输出 `{"refused":"…"}`，退出码非 0。人话挪到 stderr。
- **P4 被拒的话要能照着改。** `refused` 是一句告诉执行者下一步怎么做的话，不是错误码。
- **P5 长内容给指针。** 卡片只放预览和 `read` 指针，全文用 `read <资源> --offset --limit` 分页取。
- **P7 产品就是这个 skill。** CLI、命令清单、钩子声明、方案副本都生成在 skill 目录里（缺省 `cli/`），SKILL.md 用相对 skill 目录的路径调用它；名字缺省沿用原 skill 名，用户要改名走 `skr rename`（目录、SKILL.md 的 name、链接一起改）。CLI 放到 skill 外面 = 手册和工具分家，搬走一个另一个就坏。
- **P6 同一本清单能导出成各家格式**（Anthropic / OpenAI / MCP / Gemini …），宿主支持哪种就挂哪种，命令本身不改。各家格式的差异记在 `formats/`，持续更新。

## 二、循环（L）

工具没有自己的循环，就把循环写进手册，下一步由工具算。

- **L1 `next <主体> --json`：工具从记录推出还剩什么，列成卡片。** 每一轮先调它；会话断了、换了 agent，从这里接着做。
- **L2 停止条件由工具给。** 只剩 `attention` 卡片：把问题原样交给用户，停下等回答；清单为空：做完了。
- **L3 第 0 步：用户刚说了话，先记再做。** 用户的回答只在聊天里，工具看不到。所以每张等回答的卡片都带 `on_reply`：
  用户回了要跑的那条命令，已经填好，只留 `<他>` `<原话>` 这几个空。
- **L4 一份计算。** 看板上的「还剩什么」和 `next` 必须是同一份计算。两边各算各的，一定会出现「看板上待测、执行者手里没有卡片」。
- **L5 卡片的形状。** `kind` + `title`（是什么）+ `note`（怎么做：一条可照抄的命令）+ `read`；`attention` 另带 `question`（原样交给用户，不改写）和 `on_reply`。
- **L6 中断恢复。** 长时间没动静的主体出 `stalled` 卡片：先查实际状态，别重复已经做过的外部动作。
- **L7 停不停由工具定，并接到宿主的续跑机制上。** 循环只写在手册里，agent 做到一半就可能自己停下。
  所以每个 CLI 都要能回答一个问题：这一轮该不该停（还有执行者能做的卡片 → 不停，并把下一张卡片作为理由交回去；
  只剩 attention 或清单为空 → 停）。各家宿主让 agent 继续干活的方式不一样（停止钩子、自驱动循环、无头模式反复调用……），
  接法记在 `hosts/` 里，带出处，和 `formats/` 一样持续更新；落地方式是一条 `stop` 事件、`continue` 方式的钩子（见 K）。
- **L8 续跑要有刹车。** 同一张卡片连续被交回去好几次还没变，说明卡住了：放它停，并把卡住的那张交给用户，别无限循环。

## 三、人的闸门（H）

- **H1 执行者不能替人点头。** 批准、拍板、确认的 `--by` 写成执行者自己（executor / agent / 执行者 …）一律拒收。
- **H2 原话照抄。** `--quote` 是人说的原话，不是复述；页面上能直接写回的，就让人在页面上写，不经过转述。
- **H3 每次点头另记一条进审批表**（谁、什么、原话、经由哪里）。主记录被覆盖了也查得回来。
- **H4 事实和决定分开。** 「查实的事实」收口要指出事实在哪（某次运行、某份证据）；人的回答只能走「记决定」那条命令。
- **H6 批准跟着内容走，不跟着文件指纹走。** 手册别处改了字、重出的方案逐字没变：批准沿用并另记一条（via=carried）；方案内容一变，必须重新请人批。
- **H5 一句话答了几件事**：命令支持一次记几条；选了某个选项，把选项连同后果原样存下（推荐后来改写了也对得上）。

## 四、代码定，模型判（J）

- **J1 能变成检查的经验，就变成检查**，并删掉手册里那段原文；变不成的，才留在提示里，由 `context` 之类的命令按需递给执行者。
- **J2 代码给候选，模型确认或否决并写理由。** 例：工具按「复用 → 启动 → 新建」选一台设备并占上，执行者只核对工具看不出的（账号、页面），不对就 `reject --why`，工具换下一台。
- **J3 谁、何时、在哪、几个、什么状态由代码定**；值不值得、对不对由模型判。

## 五、存储（S）

- **S1 每样状态只有一个正本。** 要持久、会被并发改、要事务的（租约、审批、待办、结论）放 SQLite；
  文件只用于有名字的产物（证据原文、报告、导出），或人要直接读写的资产（用例、知识）。
- **S2 派生的可以重建。** 从文件建的索引按内容哈希增量重建，任何时候能完整重建，所以不算双写。
- **S3 不整文件改写共享的 JSON。** 几个写者对同一个 JSON 读改写、没有锁，就会丢更新。要么改进 SQLite，要么加锁并只由一个命令写。
- **S4 记录要带时间和来源**（哪个命令、谁），流程才能按时间归轮、回溯。
- **S5 运行里记下当时的手册和协议版本**，结论才知道是在哪套规矩下得出的。
- **S6 每条知识先定归属层：工具 / 项目 / 用户。** 对所有用户都成立的（做法、判据）进工具的代码和手册；只对这个项目成立的（账号、构建命令、危险操作）进项目知识；
  只对这个人、这台机器成立的（代理规则、显示器、个人习惯）进用户自己的配置。手册里「记一下」这类引导必须先让 agent 判层再写，
  不然用户随口一句「我这边还要 …」会被写进工具，发给每个用户（实测：一位用户的代理配置被写死进了开源工具的代码和手册）。

## 六、本机服务（V）

- **V1 一个本机服务，按插件挂各自的页面。** 每个 skill 改造出来的看板是一个插件，共用一个端口、一份进程。
- **V2 首屏只带空壳。** 大页面的面板按需取；数据变了先给上一版，后台重新生成。
- **V3 健康检查报自己的进程号**；端口上的服务不认识当前项目时，按这个号接管，不靠某个 HOME 底下的记录。
- **V4 测试和批处理不顺手起共享服务**：后台起的服务活得比调用久，会占住缺省端口。
- **V5 页面上写回走同一条命令**（服务只转交，不补任何字段），只收本页发来的请求。

## 七、宿主钩子（K）

手册里「必须先 X 再 Y」「做完要 Z」「别中途停」这类要求，只写在提示里就会被忘；能挂到宿主事件上的，挂上去。

- **K1 写一份可移植的声明，不手写某一家的配置。** 一条钩子 = 事件（`before_tool` / `after_tool` / `prompt` / `stop` / `session_start`）
  × 对象（`shell` 跑命令 / `write` 写文件 / `any`）× 匹配（对命令行或文件路径的正则）× 调哪条命令 × 方式（`block` 拦下 / `remind` 提醒 / `continue` 续跑）。
  各家的事件名、工具名、输入输出形状由适配层翻译（Claude Code / Codex / Gemini CLI / Cursor）。
- **K2 钩子只调命令，判断在命令里。** 命令返回 `{decision, reason}`，或 `next` 形状的卡片（还有执行者能做的 → 续跑 / 提醒，理由是第一张卡片；只剩 attention 或空 → 放行）。钩子脚本里不藏逻辑。
- **K3 拦下要给能照着做的理由（同 P4）；钩子自己出错一律放行**，原因写进 stderr。坏掉的钩子不能把 agent 锁死。
- **K4 续跑有刹车（L8）。** 同一会话、同一理由连续续跑到上限就放停，并把卡住的那张交给用户；各家自带的上限（Claude Code 8 次、Cursor 5 次）之外再加一道。
- **K5 安装是合并，不是覆盖。** 只替换本工具登记的那几条，别人的钩子和配置原样保留；重装不重复。
- **K6 各家规格记在 `hosts/`**，带出处、核对日期、没核实的点；某家做不到的（Gemini 的 before_tool 不能不拦截地注入提示、Codex 的钩子要先信任）在方案里写明退路。

## 八、自我迭代（R）

- **R1 每次分析、出方案、检查都记一条执行记录**：输入的指纹、产出、用了哪版判据。
- **R2 用户说「不对」，记下原话和哪一条判据错了**；下一次启动先读最近的「不对」。
- **R3 判据本身也改**：一条反馈说明某条判据错了或缺了，就改这篇文档并在执行记录里留版本。
